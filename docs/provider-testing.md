# Provider acceptance checks

Run `npm test`, `npx tsc --noEmit`, and `npm run lint`. Tests execute the production runtime against local HTML fixtures. Media timing is controlled in the fixtures; native playback must also be checked on a device.

On both iOS and Android:

1. Start with no providers. Confirm the Websites screen offers Add provider and no preconfigured website.
2. Create a provider with two series pages. Check browser history, loading errors, duplicate page rejection, selection previews, surrounding element/undo, and advanced selectors. Learn the episode selection from a series with only one episode, then test it on a longer series: navigation links and unrelated numbers must not enter the selection.
3. Open an episode and play the primary player in Playback tracking. Advancing time and a valid duration must enable Continue without requiring a resume test. Video options contains the optional automatic resume check, its seek/restore explanation, retry, and playback help. Check success, a non-seekable player, and a check with no response: after seven seconds it must show a retryable failure, while Continue remains available for verified progress. Changing player, page, step, or closing the creator must cancel the pending feedback timer. Repeat with several videos, accessible frames, and cross-origin embedded players. For a placeholder player, wait longer than 20 seconds before tapping the placeholder and pressing Play: both the wizard and main browser must keep waiting without claiming incompatibility, then discover the video and track it. Test a delayed video inside an iframe and confirm a saved resume position is applied after activation.
4. When progress cannot be verified, confirm the failure warning suggests the primary player, explains possible site incompatibility, and requires an explicit acknowledgement before saving anyway. A skipped or failed resume check must not require this acknowledgement. Save with progress verified and resume unverified: Review must identify resume as optional, and Settings and the website chooser must show playback tracking ready without falsely marking resume verified.
5. Finish the wizard and confirm Review automatically checks both examples, including canonical redirects and delayed page content. Save after both pass; failed checks must explain which example and selection need correction, with a working retest button. Check that navigation away or canceling a check cannot validate another page. Open the provider, watch, leave, and resume from history. Change episodes and confirm the correct title, episode, duration, and saved position.
6. Edit without losing the provider ID. Cancel and check discard confirmation. Delete a provider, create another, and confirm IDs remain unique.
7. Simulate a failed storage write. Saving must keep the wizard open; a subsequent retry must work. Confirm backups and legacy history still load.
8. Check approved aliases, startup preference, provider switching, and deleted-provider history. On Home, confirm the website fills the content area without a persistent top toolbar. Back, forward, reload, website selection, and playback details belong in the bottom accessory; verify the iOS accessory also works when the tab bar minimizes. In both the creator and main browser, trigger `window.open` and a `target="_blank"` link. Pop-ups must stay blocked without changing the page or showing an approval prompt; accessible embedded players must keep working. A link or redirect to an unapproved website in the current window must be blocked first and show a native prompt with the provider name and exact destination origin. Cancel must preserve the page and whitelist; retrying the link should ask again. Add and continue must approve the origin and open the original destination URL, including its path and query. On Home, confirm the alias persists after restarting and appears when editing the provider. In the creator, confirm the alias enters the draft and persists when the provider is saved; discarding the draft must discard its new aliases. Approved origins must open other paths without further prompts. Duplicate requests while a prompt is open must not stack dialogs. Failed saves must keep navigation blocked and allow retry. Changing page, reloading, switching provider, or leaving the screen during a prompt/save must prevent its delayed navigation. Unsupported schemes must remain blocked without offering to whitelist them.
9. Test small screens, landscape, large accessibility text, screen readers, keyboard avoidance, dark mode, and light mode. Confirm the compact creator panel leaves the website visible and its details scroll. Each step should have one prominent footer action: Continue for website setup; Use this page until two examples are chosen; Select title/episodes/total until a valid selection enables Continue; Continue once playback progress is verified; and Save provider on Review. During selection, Browse must remain reachable even with details hidden. Previous, browser navigation, and details controls should look quieter than the primary action. Confirm Selection tools reveals Parent, Undo, and the CSS selector, Video options reveals optional resume/retry/help, and Review's Edit setup or retest reveals correction controls. Failed example checks should show Retest without opening that disclosure. On iOS, Close must use the native header button without a rectangular button nested inside it; it must retain discard confirmation and be disabled while saving.
10. Test an ongoing series with three released episodes out of twelve, and a paginated series with fifty listed episodes out of two hundred. Repeat on the second pagination page. Example checks must pass without opening a video or requiring the listed count to equal the announced total; Review must show both counts separately. Repeat with an unknown announced total (`??`, `TBA`, `N/A`, or `Unknown`): selection and Review must pass, Review must show "total unknown", and saving and playback tracking must work. Actual episode numbers must still be numeric. Missing or ambiguous total selections must still fail. An unknown total must not mark the series finished or infer a total from the listed episodes. When a numeric total becomes available, history must update it; if the site later shows an unknown marker again, retain the previously known total.
11. Watch part of an episode, then reopen its series page. The episode link must show the green background filled to its saved playback percentage, even before activating a placeholder player. Confirm the fill updates during playback and follows the actual episode numbers on subsequent pagination pages. Unwatched episodes, unrelated navigation links, and other series must not inherit the fill. The same exact title and episode numbers must share saved highlights and resume positions across providers, including before placeholder activation. Legacy history without a provider ID should still be highlighted. Clear the saved progress and confirm the website's original episode background returns.
12. Play two series in sequence. Watch List should default to Recently played, with the most recently played series first. Paused page visits, episode selection, seeking, and manual edits must not advance the playback date. Verify A–Z and Z–A remain available with search and the in-progress filter. Legacy entries without dates should appear after dated entries, ordered by name. Restart and restore a full backup to confirm dates persist. Play the same title through another provider and confirm one shared Watch List entry retains all episode progress and the largest known announced total. Switch from episode 12 of 24 to a provider reporting 12 total: the entry must remain in progress, with highlights available on both providers. Unknown totals must retain the known count; a larger announced total must update it. Complete or drop a series, then advance playback on an earlier episode: it must return to the in-progress list without losing the highest watched episode. Paused visits, episode selection, seeking, and repeated playback timestamps must preserve completion/drop status. Resume must also be available for completed entries on both platforms. Restart and restore a full backup to verify the new completion state persists, including a rewatch with historical final-episode progress above 90%. Confirm the saved provider and main episode URL open correctly from Watch List; repeat with providers sharing an approved alias and with legacy history lacking a provider ID. A removed website with no matching configured provider should show the website chooser.
13. In Settings, choose Export watch list and save/share `watch-list.json`. Confirm it contains all history, including finished and manually added series, regardless of Watch List filters. Each entry must contain only `name`, `highestWatchedEpisode`, `totalEpisodes` (null when unknown), and `finished`. Confirm no website configuration, URLs, provider IDs, playback dates, or per-episode details are present. Check an empty history exports `[]`; simulate unavailable sharing or a file write failure and confirm the error allows retry. Verify full Backup and Restore still include all data and use their separate backup file.

On iOS 26 with an Xcode 26 build, check native Liquid Glass buttons and surfaces in the creator, website picker, browser accessory, and provider settings. Confirm native text fields remain editable when the keyboard appears and provider values load when editing. Check system appearance and Reduce Transparency. Older iOS versions should show standard native buttons and opaque system surfaces. Android should retain its existing controls.

In the creator, expandable controls should retain their labels and show a right chevron when closed and a down chevron when open. Check Approved website aliases, Selection tools, Video options, Edit setup or retest, and Details. Expanded tools must appear below their own control, indented with a separator and comfortable vertical spacing. Review's optional retest buttons must stay inside its expanded group; failed checks must retain their visible retry action beside the result. Screen readers should announce the expanded or collapsed state. Confirm ordinary actions remain visually distinct from expansion controls, text fields fill the available group width, and the panel still leaves the website visible on small screens.

In iOS Settings, verify the Websites form with no websites, one website, and enough websites to scroll. Each entry should show its name, address, playback status, compact Open/Edit/Delete actions with matching secondary button styles, and an Open on startup switch without a stretched empty card. A sole website must open automatically, with its startup switch on and disabled; the footer must explain why. Adding a second website must enable startup choice and retain the first website's preference. With multiple websites, switching startup to another website must turn the previous switch off, and turning the selected switch off must clear the preference. Deleting back down to one website must make the remaining website open automatically. Repeat after restarting, restoring a backup, and after a failed preference write. Confirm Delete names the website, allows cancellation, preserves watch history, and reports write failures. Check long names and Dynamic Type without losing access to any action, and confirm backups remain accessible below the form.

For iOS scroll minimization, start from the website chooser, select a provider, and scroll a long page down and back up. Repeat after switching providers and after restarting with a default provider. The tab bar and accessory must minimize and expand together; the inline accessory must fit with back/forward available, icon-only reload, and a native menu for Websites and Playback details. Open and close both sheets while minimized, then confirm website scrolling still minimizes the accessory. Verify navigating between tabs and following an episode from history preserves the current provider and URL.

Keep the iOS browser's black background on `NativeTabs.Trigger.contentStyle`. The Home layout wrapper and WebView container must remain free of background styling while browsing: styled native wrapper views can prevent UIKit from associating the website's scroll view with tab minimization. Do not work around this by remounting the tab navigator when providers change.

The runtime reads standard HTML5 video in each frame and relays media samples through its parent frames. Only the main page sends series metadata and native runtime messages. Providers are always user-created.

For cross-origin playback, use a rebuilt Android development app (`npm run android`) after the postinstall WebView patch, and an iOS build. Test a player hosted on another origin, nested player frames, an advertisement beside the selected player, a video created after tapping a placeholder, and a player frame replaced or navigated between episodes. Verify one sample per video, progress only from the chosen player, the optional one-second seek/restore test, and saved resume after metadata becomes available. Commands sent by the creator must retain the main-page document guard, then use the destination frame's document ID at each relay hop; choosing a player, testing resume, and retrying playback must all work through nested cross-origin frames. History must retain the main series URL and provider ID, never the iframe or media URL. Reload, navigate away, restore browser history, and switch providers while messages are queued: stale frame samples and commands must not affect the new page. Pause playback and seek manually; neither should advance the recent playback date. Embedded frames must not request navigation approval merely because their origin differs; top-level navigation approval and blocked pop-ups must still work. Repeat on an Android WebView without `DOCUMENT_START_SCRIPT` support: accessible players should remain usable, and inaccessible players must remain unverified with an actionable device limitation message. The patch is tied to react-native-webview 13.16.1 and must be reviewed before upgrading that dependency.
